# یار برنامه‌نویس: چت‌بات فارسی با React و Node.js

یه چت‌بات فارسی با **رابط React** و **سرور Express**. کلید API فقط روی سرور می‌مونه و هیچ‌وقت به مرورگر نمی‌رسه.
ویژگی اصلیش **حالت آموزشی**ـه: وقتی روشنش کنی، زیر هر پاسخ می‌بینی پیامت از مرورگر تا مدل هوش مصنوعی و برگشت چه مسیری رفته و هر مرحله توی کدوم فایل اتفاق می‌افته.

## ویژگی‌ها

- کار با **Gemini** یا **هر سرویس سازگار با OpenAI** (با یه خط تنظیم عوض می‌شه)
- رابط کاملاً فارسی و راست‌چین، با فونت وزیرمتن که داخل پروژه‌ست (بدون نیاز به گوگل‌فونت)
- پاسخ جریانی (streaming): جواب کلمه‌به‌کلمه نمایش داده می‌شه
- **حالت آموزشی**: «پشت صحنه»‌ی هر پاسخ، همراه با اسم فایل‌ها، پرامپت سیستمی و پیام واقعی که به مدل رفته
- **تور راهنما** برای کاربر جدید (۴ قدم) که با دکمه‌ی «؟» دوباره باز می‌شه
- اگه سرور خاموش یا کلید API نباشه، به‌جای ارور گنگ، راه‌حل قدم‌به‌قدم نشون داده می‌شه
- دکمه‌ی توقف پاسخ، دوباره امتحان کردن بعد از خطا، تم روشن و تیره

## پیش‌نیازها

1. **Node.js** نسخه‌ی ۱۸.۱۱ یا بالاتر (نسخه‌ی LTS رو از [nodejs.org](https://nodejs.org) نصب کن)
2. یه **کلید API** از یکی از این دو راه:
   - **Gemini (پیش‌فرض):** وارد [Google AI Studio](https://aistudio.google.com/) شو، از منوی کناری «Get API key» و بعد «Create API key» رو بزن. کلیدهای جدید با `AQ.` شروع می‌شن (کلیدهای قدیمی‌تر با `AIza`)؛ هر دو درستن.
   - **سرویس سازگار با OpenAI:** کلید، آدرس و اسم مدل رو از سرویس‌دهنده‌ات بگیر (بخش «انتخاب سرویس هوش مصنوعی» پایین‌تر).

   دسترسی به هر سرویس به کشور و شرایط استفاده‌ی خودش بستگی داره. قبل از شروع، شرایط و سهمیه‌ی رایگان رو خودت چک کن.

## راه‌اندازی

توی ترمینال، داخل پوشه‌ی پروژه:

```bash
# ۱) نصب پکیج‌ها (چند دقیقه طول می‌کشه)
npm install

# ۲) ساخت فایل تنظیمات
#    ویندوز:
copy .env.example .env
#    مک و لینوکس:
cp .env.example .env
```

بعد فایل `.env` رو باز کن و کلیدت رو جلوی `GEMINI_API_KEY=` بذار (برای سرویس دیگه، بخش «انتخاب سرویس هوش مصنوعی» رو ببین):

```
GEMINI_API_KEY=AQ.Ab...
```

```bash
# ۳) اجرا
npm run dev
```

حالا آدرس **http://localhost:5173** رو توی مرورگر باز کن.

> اگه بعد از اجرا فایل `.env` رو عوض کردی، سرور رو ببند (`Ctrl + C`) و دوباره `npm run dev` بزن.

## نسخه‌ی نهایی (بدون حالت توسعه)

```bash
npm run build
npm start
```

بعد **http://localhost:3001** رو باز کن. توی این حالت، سرور خودش فایل‌های رابط رو هم می‌ده.

## انتخاب سرویس هوش مصنوعی

پیش‌فرض Gemini ـه. اگه Gemini برای شبکه‌ی تو یا کاربرهات کار نمی‌کنه (مثلاً خطای ۴۰۳)، می‌تونی از هر سرویسی که API سازگار با OpenAI داره (مسیر `/chat/completions`) استفاده کنی. توی `.env` این چهار خط رو بذار:

```
LLM_PROVIDER=openai
OPENAI_API_KEY=کلید-سرویس
OPENAI_BASE_URL=https://آدرس-سرویس/v1
OPENAI_MODEL=اسم-مدل
```

آدرس و اسم مدل رو از مستندات همون سرویس‌دهنده بخون. بعد از تغییر `.env`، سرور رو ری‌استارت کن. بقیه‌ی پروژه (رابط، حالت آموزشی، تور) هیچ تغییری نمی‌خواد.

## اگه خطا دیدی

| پیام یا مشکل | معنی و راه‌حل |
| --- | --- |
| «سرور خاموشه» یا «سرور در دسترس نیست» | `npm run dev` اجرا نیست. توی ترمینال اجراش کن. |
| «نیاز به کلید API» | فایل `.env` رو نساختی یا کلید رو توش نذاشتی. بعد از ساختنش سرور رو ری‌استارت کن. |
| «کلید API معتبر نیست» | کلید رو دوباره کپی کن. نباید فاصله یا گیومه داشته باشه. |
| «سهمیه‌ی درخواست‌ها پر شده» | چند دقیقه صبر کن، یا سهمیه‌ات رو توی داشبورد سرویس ببین. |
| «این درخواست رو قبل از رسیدن به API رد کرد (خطای ۴۰۳)» | بخش «اگه خطای ۴۰۳ گرفتی» پایین‌تر. |
| «پشتیبانی نمی‌کنه» (REGION) | سرویس برای بعضی شبکه‌ها و کشورها محدوده. این از طرف پروژه نیست. |
| «جواب نداد» یا «اتصال برقرار نشد» | سرور به سرویس نمی‌رسه. بخش «اگه سرور به سرویس نمی‌رسه» رو ببین. |
| پورت اشغاله | توی `.env` یه `PORT=3002` بذار. |

## اگه خطای ۴۰۳ گرفتی

اگه توی ترمینال خطای `403` با یه صفحه‌ی HTML (مثلاً «Error 403 (Forbidden)») دیدی، یعنی سرویس درخواست رو **قبل از رسیدن به API** رد کرده. این معمولاً به‌خاطر آی‌پی یا منطقه‌ی شبکه‌ست، نه کلید تو و نه کد پروژه. دو راه داری:

1. شبکه‌ای رو امتحان کن که سرویس برای اون پشتیبانی می‌شه (به شرایط استفاده‌ی سرویس هم توجه کن).
2. از سرویس دیگه‌ای استفاده کن که برای شبکه‌ی تو در دسترسه (بخش «انتخاب سرویس هوش مصنوعی»).

## اگه سرور به سرویس نمی‌رسه

**علامتش:** بعد از ارسال پیام، سه‌نقطه‌ی «در حال نوشتن» تا حدود ۳۰ ثانیه می‌مونه و بعد خطای «جواب نداد» یا «اتصال برقرار نشد» میاد.

**دلیل رایجش:** سرور این پروژه با Node.js اجرا می‌شه و Node تنظیمات پروکسی مرورگر یا افزونه‌ی وی‌پی‌ان رو نمی‌خونه. یعنی ممکنه مرورگرت به سرویس برسه ولی سرور نرسه.

**تست سریع:** توی یه ترمینال دیگه بزن (ویندوز: `curl.exe`) و آدرس سرویس خودت رو بذار، مثلاً برای Gemini:

```bash
curl -I -m 10 https://generativelanguage.googleapis.com/
```

اگه بعد از ۱۰ ثانیه جواب نیومد یا خطا داد، سرور هم نمی‌تونه برسه.

**راه‌ها:**

1. برنامه‌ی شبکه‌ات رو توی حالتی بذار که کل سیستم رو پوشش بده (معمولاً اسمش TUN یا System-wide ـه)، نه فقط مرورگر.
2. یا آدرس پروکسی محلی همون برنامه رو توی `.env` بذار و سرور رو ری‌استارت کن:

```
LLM_PROXY=http://127.0.0.1:10809
```

(عدد پورت رو از تنظیمات برنامه‌ات بخون؛ باید پورت **HTTP** باشه. بعد از آپدیت پروژه، یه بار `npm install` هم بزن.)

دسترسی به هر سرویس به کشور و شرایط استفاده‌ی خودش بستگی داره. قبل از استفاده، شرایطش رو چک کن.

## نقشه‌ی پروژه

```
persian-chatbot/
├── server/
│   ├── index.js        ← سرور Express: اعتبارسنجی پیام، صدا زدن مدل (Gemini یا OpenAI-سازگار)، فرستادن جواب جریانی
│   └── prompt.js       ← پرامپت سیستمی: شخصیت و قوانین ربات
├── src/
│   ├── App.jsx         ← منطق اصلی چت (state، ارسال پیام، حالت آموزشی)
│   ├── lib/chat.js     ← ارتباط مرورگر با سرور و خوندن جواب جریانی
│   ├── components/
│   │   ├── Message.jsx       ← نمایش یه پیام
│   │   ├── Markdown.jsx      ← نمایش امن Markdown (بولد، لیست، کد)
│   │   ├── BehindScenes.jsx  ← «پشت صحنه» برای حالت آموزشی
│   │   ├── Tour.jsx          ← تور راهنما
│   │   └── SetupCard.jsx     ← راهنمای راه‌اندازی وقتی سرور یا کلید نیست
│   └── styles.css      ← همه‌ی رنگ‌ها و ظاهر (متغیرهای بالای فایل)
├── .env.example        ← نمونه‌ی تنظیمات
└── vite.config.js
```

## مسیر یه پیام (همونی که حالت آموزشی نشون می‌ده)

1. `src/App.jsx` پیام و تاریخچه رو با `POST /api/chat` می‌فرسته.
2. `server/index.js` پیام‌ها رو چک می‌کنه، پرامپت سیستمی (`server/prompt.js`) رو اضافه می‌کنه و با کلید API به مدل می‌فرسته.
3. مدل جواب رو تکه‌تکه برمی‌گردونه و سرور اون رو به مرورگر پاس می‌ده (SSE).
4. `src/components/Markdown.jsx` هر تکه رو به متن قشنگ تبدیل می‌کنه.

## شخصی‌سازی

- **لحن و شخصیت ربات:** `server/prompt.js`
- **سرویس و مدل:** `LLM_PROVIDER` و `GEMINI_MODEL` (یا `OPENAI_MODEL`) توی `.env`
- **سوال‌های پیشنهادی و پیام خوش‌آمد:** بالای `src/App.jsx`
- **رنگ‌ها:** متغیرهای `:root` بالای `src/styles.css`
- **متن‌های تور:** `src/components/Tour.jsx`

## نکات امنیتی

- کلید API فقط توی `.env` روی سرور می‌مونه. `.env` توی `.gitignore` هست؛ **هیچ‌وقت اون رو آپلود نکن**. اگه کلیدت جایی لو رفت، از داشبورد گوگل حذفش کن و یه کلید جدید بساز.
- کاربر نمی‌تونه پیام با نقش «system» بفرسته. سرور فقط پیام‌های `user` و `assistant` رو قبول می‌کنه و پرامپت سیستمی رو خودش اضافه می‌کنه.
- طول پیام، تعداد پیام تاریخچه و تعداد درخواست هر نفر محدوده.
- پرامپت سیستمی توی این پروژه **محرمانه نیست** (حالت آموزشی نشونش می‌ده و کد هم متن‌بازه). هیچ‌وقت رمز یا اطلاعات خصوصی توی پرامپت نذار؛ ربات رو می‌شه فریب داد تا چیزی که می‌دونه رو بگه.
- محدودکننده‌ی تعداد درخواست داخل حافظه‌ست و با ری‌استارت سرور ریست می‌شه. اگه پروژه رو عمومی منتشر کنی، هر کس می‌تونه از سهمیه‌ی کلید تو مصرف کنه. قبلش ورود کاربر و محدودیت سخت‌گیرانه‌تر اضافه کن.

## ایده‌های تمرین (مهندسی معکوس)

1. توی `server/prompt.js` لحن ربات رو عوض کن و ببین جواب‌ها چه تغییری می‌کنن.
2. یه دکمه‌ی «کپی» کنار بلوک‌های کد اضافه کن (`Markdown.jsx`).
3. تاریخچه‌ی گفتگو رو توی `localStorage` ذخیره کن (`App.jsx` و `lib/storage.js`).
4. یه حالت جدید بساز که ربات فقط سوال بپرسه و جواب مستقیم نده.
